# Quick Task 260507-i16 — Resolve `EUNSUPPORTEDPROTOCOL workspace:*` for `firebase deploy`: Summary

**One-liner:** Adopted `isolate-package` via the `firebase-tools-with-isolate` fork to rewrite pnpm `workspace:*` refs into `file:` refs at deploy time, fixing the Cloud Build `EUNSUPPORTEDPROTOCOL` blocker; verified end-to-end by deploying `auth` (5 functions) and `trustsafety` (1 function) clean to `southamerica-east1`.

## Outcome

**Primary success criterion: ACHIEVED.** Zero `EUNSUPPORTEDPROTOCOL` or `workspace:*` errors in any deploy log across all 8 codebase deploy attempts. The workspace-protocol error class is permanently eliminated from the Cloud Build pipeline.

### What Now Works

- `pnpm --filter ./packages/shared build` → compiled `lib/` JS + `.d.ts` for downstream consumers (PWA, Functions).
- `firebase deploy --only functions:<codebase>` runs predeploy build chain → isolate-package generates a self-contained `functions/<codebase>/isolate/` directory → Cloud Build npm-installs the rewritten lockfile (no `workspace:*`, no error) → image builds → Cloud Run deploys.
- 6 functions live in `southamerica-east1`: `auth.{anonUpgrade,botGenerateLinkToken,discordExchange,unlinkDiscord,verifyAge}`, `trustsafety.reportUser`.

### What Remains Blocked (Out of Scope per Plan)

- `consent`, `challenges`, `wearables`, `gamification` — pre-existing TypeScript errors in their own source code prevent the predeploy `tsc` step from succeeding. These are documented in deferred items and need their own quick tasks.
- `events`, `b2b` — predeploy passes, deploy fails on missing Firebase secrets (`QR_SIGNING_KEY`, `PARTNER_EMBED_SIGNING_KEY`). Operator action required (`firebase functions:secrets:set`).

### 1. [Rule 3 — Blocking] Replaced `--filter @gamechangers/<name>` with path filters `--filter ./functions/<name>`

- **Found during:** Task 4 (first deploy attempt).
- **Issue:** firebase-tools-with-isolate routes predeploy commands through `node_modules/cross-env/src/bin/cross-env-shell.js`. On Windows, cross-env-shell mangles `@scoped` package args, leaving pnpm with an empty filter that matches zero projects: `No projects matched the filters in "..."`.
- **Reproduction:** `node node_modules/cross-env/src/bin/cross-env-shell.js "pnpm --filter @gamechangers/shared build"` → empty result. Same with `./packages/shared` → builds correctly.
- **Fix:** Switched all 24 predeploy entries (8 codebases × 3 builds) to path filters. Functionally identical — pnpm resolves `./functions/auth` to the same workspace package as `@gamechangers/functions-auth`.
- **Files modified:** `firebase.json`.
- **Commit:** `4b678b5`.

### 2. [Rule 3 — Blocking] Removed deprecated `"isolate": true` flag from `firebase.json`

- **Found during:** Task 4 (second deploy attempt).
- **Issue:** firebase-tools-with-isolate v15.16.0 emits `! functions: The 'isolate' flag in firebase.json is deprecated and no longer needed — monorepo detection is now automatic. Please remove 'isolate' from your functions config.` Then proceeds to refuse isolation because the flag is interpreted as opt-out behavior in the new auto-detect path.
- **Source:** `RESEARCH.md §P1` referenced this flag based on documentation that predates the auto-detection rollout in v15.16.0.
- **Fix:** Removed `isolate: true` from all 8 codebase entries.
- **Files modified:** `firebase.json`.
- **Commit:** `d24c5f3`.

### 3. [Rule 3 — Blocking] Added `"files": ["lib"]` to all workspace packages being isolated

- **Fix:** Added `"files": ["lib"]` to `packages/shared`, `functions/shared`, and all 8 function codebases.
