<objective>
Implement authentication and Discord linking per AUTH-01..12: Anonymous Auth on boot (eliminates Discord-to-app conversion friction at the consent step per Pitfall #4), email/password sign-in/up + reset, Discord OAuth bridge via custom-token Cloud Function with KMS-encrypted refresh tokens, age gate at 16+ (D-14 LOPDP Art. 24), and phone-auth as alternative. The anonymous→full upgrade keeps the same uid as canonical (per ADR-008 from Plan 01) so XP, attendance, and badges survive the upgrade without merge logic.

Purpose: Enables the user to reach the platform AT ALL. Every later plan depends on a stable Firebase uid plus the Discord-link path that bridges Phase 1 community members into the platform.

Output: A boot flow that lands users anonymously, an account-upgrade flow that preserves data, a Discord-link flow that fetches identity + encrypts refresh tokens, and a 16+ age gate enforced at the Cloud Function and UI layers.
</objective>

  <behavior>
    - `discordExchange` (HTTPS callable v2 in southamerica-east1): accepts `{ code, state, pkceVerifier, firebaseIdToken?, pendingDiscordId? }` (zod-validated). Verifies state cookie matches (CSRF). Exchanges code at `https://discord.com/api/oauth2/token` with `grant_type=authorization_code`, `code_verifier=pkceVerifier`. Fetches `https://discord.com/api/users/@me` with the access_token. **Bot-link assertion:** if `pendingDiscordId` is present, MUST verify `discordUserFromOAuth.id === pendingDiscordId`; on mismatch throw `HttpsError('permission-denied', 'DISCORD_ID_MISMATCH')` AND write audit log entry `{ action: 'discord_link_id_mismatch', expected: pendingDiscordId, actual: discordUserFromOAuth.id, timestamp }` (possible CSRF/replay attack). Encrypts refresh_token via `kmsEncrypt`. Determines target uid:
        - If request includes `firebaseIdToken` of an anonymous user → uses that uid (preserves XP, per ADR-008).
        - Else → checks `/users/_lookup/discord/{discordId}` for existing mapping; if found, uses that uid; else creates new uid `discord:${discordId}`.
        Writes `/users/{uid}/private/discord` doc with `{ discordId, username, globalName, avatar, encryptedRefreshToken, linkedAt: serverTimestamp }`. Reads existing `/users/{uid}/consents/*` to build the consent bitmap; mints custom token via `getAuth().createCustomToken(uid, { consents: bitmap, hasDiscord: true, ageVerified: existingDoc?.ageVerified ?? false })`. Returns `{ customToken, isExistingUser: boolean }`.
    - `anonUpgrade` (HTTPS callable): accepts `{ method: 'email'|'phone', email?, password?, phone?, smsCode? }`. Caller MUST be authenticated as anonymous user. Calls Firebase Admin `auth().updateUser(uid, { email, password })` OR phone equivalent. Critically, does NOT change the uid — the anonymous uid is preserved (per ADR-008). Returns `{ uid, isAnonymous: false, email|phone }`.
    - `ageGate` (HTTPS callable, named `verifyAge`): accepts `{ birthDate: string in YYYY-MM-DD }`. Computes age. If <16, throws `HttpsError('failed-precondition', 'AGE_UNDER_16')` AND records the rejection in `auditLog` with `{ uid, action: 'age_gate_rejected', timestamp }`. If 16-17, sets `isMinor: true` claim AND `parentalConsentRequired: true`. If 18+, sets `ageVerified: true, isMinor: false`. Writes the birthDate to `/users/{uid}/private/identity` (NOT to `/profile/main` — birthDate is not in the basic profile per UI-SPEC and MUST never reach BigQuery; only the `age_band` derived field does).
    - `unlinkDiscord` (HTTPS callable): callable by the user themselves. Deletes `/users/{uid}/private/discord` doc. Removes `hasDiscord: true` from custom claims. Audit log entry written.
    - `passwordReset` is the standard Firebase Auth flow — no custom Function needed; the PWA calls `sendPasswordResetEmail()` directly. Use Resend as the email template provider via Firebase Auth's "Custom action handler URL" config. Document this; no code in functions/auth needed except potentially a hook for analytics.
