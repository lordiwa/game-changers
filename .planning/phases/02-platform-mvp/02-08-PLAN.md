<objective>
Build wellness challenges per CHLG-01..12 with the manual-first design discipline that mitigates Pitfall #9: 5 challenge types × 3 Bronce/Plata/Oro tiers, manual entry as the primary data path (designed BEFORE wearable SDKs in Plan 09), native phone pedometer via Web Sensor API (CHLG-04 GAP), photo + community vouching for non-wearable users, gaming-themed narrative comparisons (CHLG-06), opt-in leaderboards via aggregate documents (NEVER onSnapshot on the underlying collection — Pitfall #2), per-type anti-cheat thresholds, completion XP/badges via Plan 05's xp-events pipeline, and seasonal battle-pass progression with themed Q2 2026 season.

Purpose: Challenges drive between-event engagement. Pitfall #9: if challenges require wearables, 70% of users see greyed-out UI and churn. Pitfall #2: if leaderboards use Firestore listeners on the raw collection, reads explode at $50/day for 1K users. The manual-first + aggregate-doc patterns are the 5–10x retrofit cost mitigation in Phase 3.

Output: A user with NO wearable can browse challenges, enroll in Bronce/Plata/Oro tiers, log progress manually or via phone pedometer or photo, see live narrative comparisons, opt into leaderboard with anonymous option, complete challenges to earn XP and badges, and chase a seasonal battle pass.
</objective>
