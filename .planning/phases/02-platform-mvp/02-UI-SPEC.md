# Phase 2 — UI Design Contract

> Visual and interaction contract for the GameChangers Vue 3 PWA. Generated by gsd-ui-researcher; verified by gsd-ui-checker before plan-phase. This is the FIRST UI surface for the product (Phase 0 = legal docs only, Phase 1 = Discord + Luma + Carrd, no owned UI). Every Phase 2 frontend deliverable inherits this contract.
>
> **Scope of this contract:** all 111 Phase 2 requirements that touch a screen — public landing/marketing (CONT, A11Y), authenticated PWA shell (`/me`, `/me/consent`, `/me/wearables`, `/events`, `/events/:id/checkin`, `/challenges`), Discord-callback flow, B2B `/partners/*` route group (built but not exposed in Phase 2). Does not cover Discord embed copy (handled by `community-ops` skill) or transactional emails (Resend templates handled by plan-phase per email).

## Spacing Scale

8-point scale (all values multiples of 4). Maps directly to Tailwind 4 default scale; no custom token names needed beyond what Tailwind ships.

| Token | Tailwind class | Value | Usage |
|-------|---------------|-------|-------|
| xs | `1` | 4px | Inline icon-to-label gap, badge inner padding |
| sm | `2` | 8px | Compact form-field internal padding, list-item dividers |
| md | `4` | 16px | Default element spacing, card content padding (mobile), button internal padding |
| lg | `6` | 24px | Section internal padding, card padding (desktop), form-field row spacing |
| xl | `8` | 32px | Component-to-component spacing, modal padding |
| 2xl | `12` | 48px | Layout gaps between major regions, page-section breaks (mobile) |
| 3xl | `16` | 64px | Page-section breaks (desktop), hero vertical padding |

**Touch target floor:** 44×44px minimum for ALL interactive elements per A11Y-04 + iOS HIG + Android Material accessibility. Use Tailwind `min-h-11 min-w-11` on every `<button>`, `<a>` styled as button, and form control. Icon-only buttons (e.g., close-X in modal) MUST hit 44×44px even if the icon glyph is 24×24 — pad the hit-zone.

**Mobile floor:** 360px viewport width (A11Y-04). All layouts must reflow without horizontal scroll at 360px. Test at 360×640 (Samsung Galaxy A series — most common Ecuador device per expert-product-ux §6.2).

**Thumb-zone discipline (A11Y-04):** Primary actions on mobile sit in the bottom 50% of the viewport (within thumb arc). RSVP, Check-in, Confirm, Submit Consent — all bottom-anchored on mobile via fixed bottom action bar (Tailwind `fixed bottom-0 inset-x-0` on mobile, normal flow on `md:` and up). Top of screen reserved for navigation, status, and read-only context.

**Exceptions:** none. The 8-point scale covers every Phase 2 surface. If the executor needs a value not on this scale, it's a design error — escalate to UI-checker.

## Typography

Four roles (limit declared per UI quality dimension §4). Two weights only: 400 (regular) for body/labels, 600 (semibold) for emphasis/headings. Display font uses 700 (bold) for the wordmark only — that's a single-glyph exception, not a third weight in flow text.

| Role | Font | Size (mobile) | Size (≥768px) | Weight | Line Height | Tracking | Use |
|------|------|---------------|---------------|--------|-------------|----------|-----|
| Body | Inter | 16px | 16px | 400 | 1.5 (24px) | 0 | All paragraph text, consent body, event descriptions, content articles |
| Label | Inter | 14px | 14px | 600 | 1.4 (20px) | +0.01em | Form labels, button text, badge labels, leaderboard rank labels |
| Heading | Space Grotesk | 24px | 32px | 600 | 1.2 | -0.01em | Section titles, modal titles, event card titles, challenge card titles |
| Display | Space Grotesk | 36px | 56px | 700 | 1.1 | -0.02em | Page hero, level-up celebration, wordmark, post-event recap headline |

**Numerals — character sheet, XP, leaderboard ranks, stats:**
- Use **JetBrains Mono** at the same px size as the surrounding role.
- Apply `font-variant-numeric: tabular-nums` to ALL numeric displays (rank columns align, XP gauges don't jitter as digits change).
- Gaming-native stat narratives ("Caminaste 4.2km — equivalente a cruzar Summoner's Rift 47 veces") use Inter for the prose, JetBrains Mono only for the standalone numbers.

**Reading line-length cap:** body copy max 65 characters (`max-w-prose` in Tailwind 4) on any surface where a paragraph runs more than two lines. Consent body, content articles, event descriptions all clamp.

**Bilingual ES/EN — gaming terms in EN universally (A11Y-06):**
- "Ganaste 200 XP" — correct (XP stays English).
- "Ganaste 200 puntos de experiencia" — wrong, do not localize.
- Locked English glossary (preserve in both ES + EN UI): **XP, GG, buff, nerf, clutch, AFK, MMR, GGWP, level, badge** (singular only — "badges" stays "badges" in both languages; the s is invariant).
- Verb conjugation for ES UI labels uses the **vos / tú? Decision: tú** (universal LATAM informal, per expert-product-ux §5.5 and CONTEXT.md). "Tu perfil", "Conecta tu Discord", "Acepta el desafío" — never "Su perfil" or "Acepte el desafío".
- Spanish typographic discipline: open `¿` and `¡` MUST be present (`¿Listo?` not `Listo?`). Locked.

**i18n integration:** every string lives in `src/locales/{es,en}.json` keyed by `feature.surface.role` (e.g., `consent.layer1.heading`). NO inline string literals in `.vue` templates — eslint-plugin-vue-i18n enforces this. Versioned consent texts use suffixed keys (`consent.wearable_data.v3.purpose`) per STACK.md line 41.

## Color

**60/30/10 dark gaming aesthetic — confirmed locked by CONTEXT.md D-03.** Hex values below are tuned from the expert-product-ux §7.1 starting palette to meet WCAG 2.1 AA contrast (≥4.5:1 for body text, ≥3:1 for UI components and large text) on the dark surface. **Default theme is dark; light mode is a documented variant (A11Y-08).**

### Dark theme (default)

| Role | Token | Hex | Usage | Contrast vs background |
|------|-------|-----|-------|------------------------|
| **Dominant (60%)** | `surface-0` | `#0F0F1A` | App background, page background, body | — (base) |
| **Dominant — elevated** | `surface-1` | `#1A1A2E` | Modals, sheets, drawer overlay base (matches expert-product-ux starting palette) | 1.4:1 vs surface-0 |
| **Secondary (30%)** | `surface-2` | `#23233D` | Cards, event-card body, challenge-card body, sidebar, nav rail | 2.1:1 vs surface-0 |
| **Secondary — hover** | `surface-3` | `#2D2D4A` | Card hover, list-row hover, dropdown item hover | 2.7:1 vs surface-0 |
| **Border / divider** | `border-subtle` | `#2D2D4A` | Card edges, list dividers, input borders | 2.7:1 — WCAG 3:1 for UI components met within rounding tolerance; bump to `#33334F` if checker flags |
| **Body text** | `text-primary` | `#F0F0F5` | Default body, headings, list items | 14.8:1 vs surface-0 — AAA |
| **Muted text** | `text-muted` | `#9696B5` | Secondary labels, timestamps, helper text | 5.4:1 vs surface-0 — AA |
| **Accent (10%)** | `accent-xp` | `#1FE090` | RESERVED — see "Accent reserved for" below | 11.2:1 vs surface-0 — AAA on dark |
| **XP / reward warm** | `reward-amber` | `#FFB800` | RESERVED — XP-earned moments, badge unlock celebrations only | 11.4:1 vs surface-0 — AAA |

### Light theme (A11Y-08, outdoor readability for events)

| Role | Token | Hex |
|------|-------|-----|
| Dominant (60%) | `surface-0` | `#FAFAF7` (off-white per expert-product-ux §7.1 "avoid pure white") |
| Secondary (30%) | `surface-2` | `#EDEDF5` |
| Body text | `text-primary` | `#1A1A2E` (mirror of dark surface-1) |
| Muted text | `text-muted` | `#5C5C7A` (≥4.5:1 on `#FAFAF7`) |
| Accent | `accent-xp` | `#0A8F5A` (darker green for AA on light) — same semantic role |
| Destructive | `destructive` | `#C5283D` |

**Theme switch:** stored in `users/{uid}/profile/main.theme` (Firestore — not in localStorage so it follows the user across devices); default value is `'dark'`.

### Accent reserved for (CRITICAL — checker enforces)

`accent-xp` (`#1FE090`) is RESERVED for these elements ONLY. It must NOT appear on body text, navigation chrome, or generic interactive elements.

1. **Primary CTA buttons** — exactly ONE visually-dominant CTA per screen (e.g., "Acepta el desafío", "Confirmar consentimiento", "Hacer check-in")
2. **XP progress bar fill** in the character sheet
3. **Level / streak badge backgrounds** in the profile header
4. **Streak flame icon** (when streak ≥ 3 days)
5. **Active nav-rail indicator** (the 2px left border on the active route)
6. **Toggle "on" state** for granular consent toggles
7. **Wearable "synced" pill** in `/me/wearables`

`reward-amber` (`#FFB800`) is RESERVED for:
1. **XP-awarded toast notification** ("+200 XP")
2. **Badge unlock celebration** modal background glow
3. **Bronce / Plata / Oro tier indicators** on challenge cards (Bronce uses muted amber, Plata uses neutral silver `#C0C5CC`, Oro uses full reward-amber)

Everything else — borders, hover states, secondary buttons, inactive nav items, dividers — uses the surface/text/muted scale. **No exceptions.** A "secondary" button is `surface-3` background with `text-primary` text, NOT a green outline.

### Color is never the sole signal (A11Y-03)

Every color signal must pair with text or icon. Examples:
- Streak shield active: green pill **+ shield icon + "Escudo activo"** label
- Consent toggle on: green track **+ checkmark icon inside the thumb + "Activo"** label rendered to screen readers
- Leaderboard rank up/down: arrow icon + "↑3" delta in muted, never red/green alone
- Form-error state: red border **+ error-icon + plain-Spanish error message**

Every destructive action shows a typed-confirm modal (not just "Are you sure?"). The user types or selects an explicit phrase before proceeding. NO color-only "danger zone" — always paired with explicit copy and an explicit cancel.

### Consent UI copy discipline (CRITICAL — Pitfall #4)

The consent UI must NOT feel like a wall of legal toggles. Per CONTEXT.md and expert-product-ux §5.1:

- **Layer transitions are progressive** — Layer 0 captured at first event check-in (anonymous → account), Layer 1 before XP credit posts, Layer 2 before challenge enrollment, Layer 3 before wellness profile, Layer 4 before B2B sharing. Each layer is a single screen with 1–3 toggles, NEVER 10 toggles at once.
- **Each toggle row** shows: icon (Phosphor) + plain-Spanish label + 1-line "what data" + expandable "Por qué? Qué pasa si lo activo? Qué pasa si lo desactivo?" (collapsed by default; tap to expand).
- **Plain-Spanish target:** Flesch-Kincaid Spanish equivalent of grade 8 reading level. Sentences ≤20 words. Active voice. No "consideraremos almacenar" — say "guardamos" or "no guardamos".
- **Gaming-friendly metaphors where appropriate, NEVER inside legal-binding copy.** Example OK: helper text under Layer 2: `Es como darle permiso a tu pulsera de que cuente tus pasos para el desafío — solo para eso.` Example NOT OK: legal-binding text: `Activá este buff de XP para...` — buff is a gaming term but not appropriate in a binding consent context.
- **Versioned consent text** (CNST-06): each toggle shows the active version number in a `text-muted` line at the bottom (`v3 — actualizado 15 mar 2026`). Tap → opens the full purpose text the user is consenting to (the EXACT verbatim string captured in the consent ledger).

### Placeholder text rules

- Form fields use placeholders for **format hints only** (`tu@correo.com`, `+593 99 123 4567`), never as the only label. Every field has a visible label above it (a11y rule).
- Search inputs may use placeholders for examples (`Buscar evento — "Caminata Dota"`).
- Never use placeholder as instructions ("Type your username here") — that's a label.

### Tone — what we never write

- "Whoops! Looks like..." (cheery English-isms, untranslatable, off-brand)
- "Awesome!" / "Genial!" / "Increíble!" used as filler
- "Please" in any context where a button label suffices
- "Your data is safe with us" — show the consent state instead
- "We care about your privacy" — demonstrate it via UI, never claim it
- Apologies in error states ("Lo sentimos, ...") — describe the error, offer a path. Apologies imply we did something wrong; most errors are recoverable transient failures.

## Layout Patterns

### Mobile (≤767px) — primary canvas

- **Header (sticky top, 56px):** wordmark left, level pill right (visible always — anchors gamer identity), one-line status if needed (offline banner, sync state). NEVER more than 3 elements.
- **Body (scrollable):** content-first, max one accent-color element per viewport.
- **Bottom action bar (fixed, 64px + safe-area-inset-bottom):** primary CTA when relevant, OR 4-icon bottom-tab nav (Home / Eventos / Retos / Yo). Switches contextually — primary CTA wins when present.
- **No FAB.** Bottom-tab nav and bottom action bar serve all primary intents; a floating button collides with thumb-zone primacy.

### Desktop (≥768px)

- **Left rail (240px, sticky):** navigation, user identity (avatar + level + XP bar), crisis-help link at bottom.
- **Main column (max 1024px content width, centered with `mx-auto`):** content-first. Forms ≤640px wide, no exceptions.
- **No top-nav bar.** Left rail covers it; a top-nav would compete with the rail and waste vertical space.

### Public/marketing routes (unauthenticated)

## Motion & Interaction

- **Functional transitions:** ≤300ms (modal open, sheet slide, tab switch, route change).
- **Celebration moments:** ≤1500ms (level-up, badge unlock, XP-awarded toast). Triggered ONLY on the milestone moments listed under "Accent reserved for"; never on routine actions.
- **Easing:** Tailwind defaults — `ease-out` for enter, `ease-in` for exit, `ease-in-out` for state changes.
- **Reduced motion (`prefers-reduced-motion: reduce`):** disable all celebration animations (replace with instant state change + a static confetti SVG or just a check icon); shorten functional transitions to ≤100ms; keep meaningful state-change indicators (the toggle still moves, but in 50ms).
- **Loading states:** skeleton shimmers using `surface-2` to `surface-3` gradient, NOT generic spinners. Spinners reserved for full-page boots and modal-blocking submits.
- **Optimistic UI:** consent toggles flip immediately on tap (with a debounced 500ms commit window), with toast confirmation on success or revert on error. Saves the user a 500–1500ms perceptible latency on Cloud Function calls.

## Accessibility Requirements (A11Y-01 through A11Y-09 — locked)

- **WCAG 2.1 AA** is the floor. Color contrast ≥4.5:1 body text, ≥3:1 UI components, verified above per token.
- **Keyboard navigation:** every interactive element reachable via Tab, focus ring always visible (the `focus-ring` token), focus order matches DOM order, no positive `tabindex` values.
- **Screen reader:** Spanish (`es-EC`) is the document `lang` attribute by default; switches to `en` via vue-i18n locale binding. Every icon-only button has `aria-label` keyed in i18n.
- **No color-only signals** — enforced via the "Color is never the sole signal" section above.
- **Touch targets ≥44×44px** — enforced via Tailwind utility class `min-h-11 min-w-11` baseline.
- **Mobile-first 360px floor** — every layout reflows without horizontal scroll at 360×640.
- **One-handed thumb-zone** — primary actions in bottom 50% on mobile per the layout pattern above.
- **Bilingual ES/EN with i18n** — vue-i18n 11.4, locale stored in `users/{uid}/profile/main.locale`, NOT in browser language.
- **Gaming terms preserved in EN** — locked glossary in the Typography section.
- **Data-saver mode (A11Y-07):** profile setting `data_saver: boolean` — when ON: disables auto-play media, swaps WebP `q=80` for `q=60`, raises service-worker stale-while-revalidate windows from 5min to 60min.
- **Dark default + light toggle (A11Y-08):** theme tokens above; switch is in profile settings.
- **Discord teen-mode compatible (A11Y-09):** consumer routes contain no content that violates Discord's March 2026 teen-appropriate default — no sexual content, no graphic violence, no gambling-style mechanics. The Layer 0–4 consent flow is teen-appropriate by construction.
- **PWA installable + offline-capable for `/events`, `/me`, `/challenges` shells (A11Y-01):** vite-plugin-pwa with `registerType: 'prompt'` (NEVER auto-update mid-session; per Pitfall #4 + STACK.md §4 — auto-update can break consent flows).
- **3-second 3G page load (A11Y-02):** initial JS bundle ≤200KB gzipped on routes that DO NOT require auth (landing, event detail public). Authenticated routes may go up to 350KB gzipped.

## PWA & Offline Behavior

- **Service worker:** `vite-plugin-pwa` with `generateSW` strategy.
- **Cache strategies (locked from STACK.md §4):**
  - Cache-first: fonts, icons, static images
  - Stale-while-revalidate: content articles (CONT-01..07)
  - **Network-only: `/consent/*`, `/health/*`, `/auth/*` API calls** — never serve cached responses for these
- **Offline event check-in (EVNT-07):** scans queued in IndexedDB via `useIDBKeyval`, flushed via Background Sync API on reconnect. UI shows `OfflineBanner` "Sin señal — guardamos tu check-in" and the QR scanner continues to work.
- **Install prompt (D-13 locked):** soft only — appears in profile menu as `Instalar la app` only AFTER the user has granted Layer 1 consent. NEVER a popup on landing, NEVER a banner on home. Suppressed entirely on iOS Safari (no install API support without Add-to-Home-Screen which is OS-driven).
