<objective>
Build the events system per EVNT-01..14 + accessibility requirements A11Y-01..09: 3-tier events (Meetups / General / Club Sessions), 1-tap RSVP, waitlist auto-promote (GAP), 24h+2h Web Push + WhatsApp reminders, QR check-in via signed JWT (offline-capable via Workbox Background Sync + IDB), manual fallback search-by-username, walk-in capture (no-account), post-event feedback (consent-gated wellness opt-in), auto-generated shareable post-event card (Cloud Function rendering HTML+canvas), aggregate-stats-only Discord recap (via the bot from Plan 03), one-tap anonymous report-user flow (GAP — new trust-safety codebase), and per-event safety contact assignment. Plus full WCAG 2.1 AA compliance, mobile-first 360px floor, 44×44 touch targets, ES-primary i18n with EN gaming terms, dark default + light toggle, Discord teen-mode compatible, data-saver toggle, and PWA installable+offline shells for `/events`, `/me`, `/challenges`.

Purpose: Events are the platform's primary value moment — 90 seconds from Discord-link → consent grant → first event check-in is the success criterion in ROADMAP. Offline check-in matters because Ecuador venues have unreliable connectivity; queue+flush is the difference between a crashed meetup and a smooth one. Accessibility is non-negotiable per A11Y-* and LOPDP teen-mode mandate.

Output: Users can RSVP, get reminders, walk in or QR check-in (offline OK), see post-event recap, optionally fill wellness feedback, share recap card, and report harassment anonymously. Automated WCAG audit gates the build.
</objective>

        1. Read event; if `rsvpCount < capacity` AND `waitlistCount > 0`:
            - Find oldest waitlist attendance (`orderBy rsvpAt asc, where status == 'waitlist', limit 1`).
            - Transactionally update to `status: 'rsvp'`; rsvpCount++; waitlistCount--.
            - Send Web Push + email notification "Te promocionaron — entras al evento".

    - **`checkIn`** (HTTPS callable, called from PWA OR via service-worker offline replay):
        1. zod-validate `{ qrPayload: string, geo: { lat, lng }? }`.
        2. Verify JWT with `QR_SIGNING_KEY` from Secret Manager. If `exp < now` → throw `HttpsError('failed-precondition', 'QR_EXPIRED')`. Use claims's `eventId`, `uid`, `jti`.
        3. Read `/events/{eventId}.venue.{lat,lng,radiusMeters}`. If `geo` provided, compute haversine distance; if > radiusMeters, throw `HttpsError('failed-precondition', 'OUT_OF_VENUE')`.
        4. Idempotent write: `/events/{eventId}/attendance/{jti}` set with `{ checkedInAt: now, ...claims }, { merge: true }`. Because `jti` is the doc ID, replays are no-ops.
        5. Publish to `xp-events` Pub/Sub: `{ type: 'event_attended', uid: claims.uid, eventId: claims.eventId }`.
        6. Return `{ ok: true }`.

    - **`walkInCapture`** (HTTP onRequest, no auth required — for unauthenticated walk-ins):
