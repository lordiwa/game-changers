<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Cloud Functions runtime -> KMS | Encrypter/decrypter on a single key; over-permission would let a compromised function read OTHER cryptoKeys |
| Pub/Sub publishers -> topics | Implicit creation gives no audit trail; explicit provisioning means topic creation is recorded in audit log |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-10-01 | Elevation of Privilege | KMS IAM binding scoped too broadly (e.g., on keyring or project) would let runtime SA decrypt other keys | HIGH | mitigate | Task 1: bind role on the cryptoKey resource only, not keyring or project |
| T-02-10-02 | Tampering | KMS key destroyed accidentally -> all encrypted refresh tokens unrecoverable | HIGH | accept | Document `--scheduled-destroy-duration` 30d window in runbook; do not include destroy commands in scripts |
| T-02-10-03 | Information Disclosure | KMS audit logs disabled -> cannot prove who decrypted | MEDIUM | accept | Cloud KMS Data Access logs are NOT on by default; defer enablement to Phase 3 (cost) — note in runbook |
| T-02-10-04 | Repudiation | Implicit topic creation leaves no audit trail | LOW | mitigate | Task 2: explicit create-or-describe via gcloud; audit log captures the event |
| T-02-10-05 | Elevation of Privilege | Two SAs (real + fallback compute-default) hold encrypter/decrypter simultaneously, doubling attack surface | HIGH | mitigate | Task 1 step 4 Branch B: explicit revoke of fallback binding once real SA is identified; verify count == 1 (Major-2) |
</threat_model>
