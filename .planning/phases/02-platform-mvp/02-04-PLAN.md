<objective>
Build the LOPDP-compliant consent engine — the gate that EVERY Phase 2 Step 3+ feature passes through. Implement CNST-01..14: 10 independent consent categories with granular individual toggles (no bundling), progressive consent layers 0..4 attached to value moments, versioned consent texts, hash-chained immutable ledger + append-only audit log written transactionally, two-layer enforcement (Firestore Security Rules + Cloud Function middleware via the shared `consentGate` from Plan 01), revocation that stops processing immediately, full DSAR export with 30-day SLA, account erasure within 72 hours, daily expiry sweeper at 12-month renewal, re-consent on terms change, and B2B row-level consent verification scaffold (used by Plan 09's BigQuery views in Phase 3).

Purpose: Per ROADMAP.md Phase 2 build order, "No other feature ships until this is in place." The consent engine is the legal floor (LOPDP compliance gate) AND the technical floor (every later Cloud Function calls `consentGate(uid, category)` from Plan 01's shared module). Pitfall #1: consent enforcement two-layer; Pitfall #4: progressive layers prevent the Discord-to-app conversion crash.

Output: Users can grant, view, modify, revoke any of 10 consents at any time with immediate effect; DSAR + erasure rights honored; ledger immutable; B2B-ready row-level consent verification.
</objective>

    - **`consentGrant`** (HTTPS callable, region southamerica-east1): accepts `{ category: ConsentCategory, version: string, textHash: string, layer: 0|1|2|3|4 }`. Authenticated user only.
        1. Verifies `category` ∈ CONSENT_CATEGORIES; verifies `version` exists at `/consentTexts/{category}/{version}`; verifies `textHash` matches the doc's stored `textHash`.
        2. CHECKS isMinor: if `request.auth.token.isMinor === true` AND category ∈ LAYER_TO_CATEGORIES[4] (B2B + research + cross_border), THROW `HttpsError('failed-precondition', 'MINOR_CANNOT_GRANT_LAYER_4')` per D-14.
        3. Reads the most recent `/consentLedger` entry for hash chaining (latest by timestamp).
        4. In a `runTransaction`:
            - Set `/users/{uid}/consents/{category}` = `{ category, status: 'granted', version, textHash, grantedAt: now, revokedAt: null, expiresAt: now+365d, layer }`.
            - Append `/consentLedger/{ledgerId}` = `{ uid, category, action: 'grant', version, textHash, timestamp: now, hash: sha256(prevHash + JSON(payload) + uid + timestampMs), prevHash }`.
            - Append `/auditLog/{auditId}` = `{ uid, category, action: 'consent_grant', version, timestamp: now, hash: ledgerHash }`.
        5. After transaction commits: refresh custom claims via `getAuth().setCustomUserClaims(uid, { ...existing, consents: { ...existingConsents, [CLAIM_BITMAP_KEYS[category]]: true } })` — claim refresh propagates within 1 hour to Rules; middleware reads doc immediately.
        6. Returns `{ ok: true }`.

    - **`consentRevoke`** (HTTPS callable): accepts `{ category, reason? }`.
        1. Reads existing `/users/{uid}/consents/{category}`; if `status !== 'granted'` returns `{ ok: true, alreadyRevoked: true }`.
        2. Reads latest ledger entry for hash chain.
        3. In runTransaction:
            - Update consent doc: `status: 'revoked', revokedAt: now`.
            - Append ledger + audit entries with `action: 'revoke'`.
        4. Refresh custom claims removing the bitmap key (set to `false`).
        5. **Side-effect cascade** triggered via Pub/Sub `topic: 'consent-revoked'` with `{ uid, category }`:
            - For `wearable_data`: schedule wearable disconnect (calls Plan 09's `wearable-disconnect`).
            - For `event_participation`: cancel pending RSVPs (write to /users/{uid}/private/pendingCleanup).
            - For `b2b_*`: flag user's BigQuery changelog entries with `consent_revoked_at` (Plan 09 BigQuery view filters this).
        6. Returns `{ ok: true }`.

    - **`consentExpirySweeper`** (`onSchedule({ schedule: 'every day 03:00', timeZone: 'America/Guayaquil', region: 'southamerica-east1' })`):
        1. Queries collection-group `consents` `WHERE status == 'granted' AND expiresAt < now`.
        2. For each, transactionally sets `status: 'expired'` and appends ledger entry with `action: 'expire'`.
        3. Refreshes custom claims (removes the bit).
        4. Writes a notification doc at `/users/{uid}/notifications/{id}` with `{ type: 'consent_expired', category, expiredAt }` so the PWA prompts re-consent on next open.

    - **`dsarExport`** (HTTPS callable): accepts `{}`. Authenticated.
        1. Creates a Cloud Task with 10s delay calling `dsarRunner(uid, requestId)`. Returns `{ ok: true, requestId }`.
        2. Writes status doc `/users/{uid}/dsarRequests/{requestId}` = `{ status: 'queued', requestedAt: now }`.

    - **`dsarRunner`** (Cloud Task target, HTTP onRequest): reads ALL of the user's data scoped to `/users/{uid}/...` (consents, profile, badges, streaks, challengeEnrollments, challengeProgress, healthDaily; NOT raw healthSamples — paginate that into chunks if user opts in to raw export, but default to daily aggregates). Writes a ZIP to `gs://<project>.appspot.com/dsar-exports/{uid}/{requestId}.zip`. Generates signed URL with 7-day TTL using `getStorage().bucket().file(...).getSignedUrl({ action: 'read', expires: now + 7*24*3600*1000 })`. Sends email via Resend (template `dsar-ready`) with the URL. Updates status doc to `{ status: 'ready', readyAt, downloadUrl, expiresAt: now+7d }`. SLA: 30 days (this implementation completes in minutes; the SLA is a regulatory ceiling).

    - **`accountErasure`** (HTTPS callable): accepts `{ confirmation: 'ELIMINAR' }` (typed-confirm gate per UI-SPEC §Destructive confirmations). If confirmation !== 'ELIMINAR' throws `HttpsError('invalid-argument', ...)`.
        1. Soft-delete IMMEDIATELY (in a runTransaction):
            - `/users/{uid}/profile/main` set `deletedAt: now, displayName: '[deleted]'`.
            - Revoke ALL `/users/{uid}/consents/*` (set status: 'revoked', revokedAt: now). Append ledger entries.
            - Revoke ALL Firebase Auth sessions: `getAuth().revokeRefreshTokens(uid)`.
            - Set custom claims to `{ accountDeleted: true, ageVerified: false, hasDiscord: false, consents: {} }`.
        2. Schedule Cloud Task at now+72h calling `erasureHardDelete(uid)`.
        3. Return `{ ok: true }`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → consentGrant | Only authenticated user can grant for own uid; server validates textHash matches stored consent text; client cannot forge version |
| consentGrant Function → Firestore | Atomic transaction writes consent doc + ledger + audit; admin SDK bypass means consentGate is ONLY the Function-side check (Plan 01 Rules add second layer) |
| consentLedger / auditLog | Append-only by Functions service-account; client read on consentLedger restricted to own entries; auditLog readable only by DPO |
| client → DSAR signed URL | URL expires in 7 days; signed by Cloud Storage; can be revoked by deleting the bucket object |
| client → accountErasure | Typed-confirm gate prevents accidental deletion; soft-delete immediately revokes session |
